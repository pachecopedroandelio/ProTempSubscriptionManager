# ProTemp Subscription Manager

Private subscription tracking app for ProTemp. Tracks customers, GPS serial numbers, start dates, durations, expiration dates, renewals and TZONE suspension requests. Does **not** communicate with TZONE or automatically suspend devices.

## Deploy to Render (recommended)

1. Create a **new private GitHub repository** for this app. Upload the contents of this folder to the repository root. Do **not** replace your existing tracking repository.
2. In Render choose **New > Blueprint** and connect the new repository. Render reads `render.yaml` to create a web service and a persistent PostgreSQL database. **The database plan is paid; check Render's current pricing before approving.**
3. When Render requests `ADMIN_PASSWORD`, set a strong, unique password. Do not put the password in GitHub. `SECRET_KEY` is generated by Render.
4. After deployment, open the generated `.onrender.com` URL and log in with your password.
5. Add a customer, then add a GPS device. Expiration = activation date + subscription days.

**Important:** A PostgreSQL database is required for reliable persistence on Render. Do not use the default SQLite file on Render's ephemeral filesystem; records may disappear on redeploy. The app uses `DATABASE_URL` from Render Blueprint.

## Run locally

```bash
pip install -r requirements.txt
export ADMIN_PASSWORD='choose-a-strong-password'
export SECRET_KEY='a-long-random-secret'
python app.py
```

On Windows PowerShell replace `export` with `$env:ADMIN_PASSWORD='...'` etc. Local SQLite is fine for testing.

## Rules

- Devices are uniquely identified by serial number.
- Status: active, expiring within 7 days, expired, or manually confirmed suspended.
- Renewal: if still active, add days to the expiration date; if expired, count from today.
- Suspension status is manually marked `none`, `requested`, or `suspended`; the system never contacts TZONE.
- This starter uses one administrator password, not multiple accounts. For a larger production app add CSRF protection, audit trails, backups, and stronger authentication.
